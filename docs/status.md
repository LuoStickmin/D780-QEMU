# D780 (E6) status — 2026-11-10

## Container

`D780_0121.bin`（官方升级包，37,731,134 B）与 D750/D850 使用同一套
T1/T2/T3 密钥；解密后得到：

| 模块 | 大小 | 说明 |
|---|---|---|
| `ex1510_0100c0.bi` | 0x200002（2 MiB） | M-profile 向量：SP `0x20004878`，reset `0x0800053D` |
| `_tpj02_0110.bin` | 0x00E002 | 参数块 |
| `eg1510_012100.bi` | 0x21EDA7A（35.6 MiB） | 主镜像 |

`eg1510` 文件头：

```
0000 EA002F20          ; ARM b -> +0xBC88
0004 ... 001C 0
0020 "Ver.01.21.00"
```

没有基址向量表；真正的启动代码在文件 `0xBC88`（基址 `0x10020000` 时即
`0x1002BC88`）。

## Startup（0x1002BC88）

- 清零 `r0-r12`，`ldr sp`、`mov lr,#0`；
- 读/写 SCTLR（关 MMU、清 alignment）；
- `TTBR0 = 0x10030000`、`DACR = 0x55555555`；
- 打开 MMU；
- `VBAR = 0x10100000`；
- 各级模式栈：`0xC2D00000`、`0xC2CF8000`、`0xC2CF0000`、`0xC2CE8000`、
  `0xC2CE0000`、`0xC2CD8000`；
- 写 `0x04264000 = 0x21`、`0x04264020 = 0x153B0902`；
- `SP = [0x04008F00]`（boot SRAM 段）；
- `bl 0x100202B8`、`bl 0x1002D700`、`bl 0x10020394`。

## 页表

页表位于 `payload + 0x10000`（`0x10030000`），镜像里存的是 1 MiB 物理地址
（如 `0x00000000, 0x00100000, ...`），**没有 section 描述符位**。
`e6-prep` 对 1478 条执行 `|= 0x0C0E`（AP=rw、C/B on、section），MMU 才能
正常翻译。

## 轮询点

| 地址 | 值 | 结果 |
|---|---|---|
| `0x20022300` | 预置 1 | 通过 |
| `0x20070008` | 预置 1 | 通过（loop at `0x1002C298`） |

`0x20070008` 的循环检查 bit 0x10 / bit 0x1；bit 1 置位即可退出。

## 外设

已观察到的 E6 寄存器块：

- `0x04264000 = 0x21`，`0x04264020 = 0x153B0902`；
- `0x0428102C`、`0x04281028`、`0x04281020 = 0x00090000`；
- `0x04266000..0x04266010`：写 `0x02DC6C00`（48,000,000，48 MHz 定时器）；
- `0x04266000 = 3`。

## CPU

`0x10125EA0` 处出现 `udiv`，Cortex-A9（无 IDIV）会 undef；换成
`cortex-a15` 后 0 undefined，并发生 2 次 SVC（`VBAR=0x10100000` 的镜像内
handler 处理）。

## 当前终点

`0x1011C000` 附近循环，`0x0426/0x0428` 块尚未建模。下一步：

1. 把 `0x04200000..0x04300000` 做成寄存器堆（读回写入值）；
2. 观察 `0x04266000` 定时器相关的轮询/中断；
3. 继续记录新的 MMIO 块。

## 复现

```sh
python3 tools/run.py --payload eg1510_012100.bi --qemu qemu-system-arm --out runs/e6 --timeout 5
```

机器默认 `payload-base=0x10020000`、`flash-size=0x2400000`、`e6-prep=on`、
`cortex-a15`。
